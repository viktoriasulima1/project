# RVO / PDOK Integration Questions

Drafted from real findings during this sprint's own verification (see `docs/BRP_PDOK_Official_Data_Audit.md`). The BRP Gewaspercelen public dataset itself was fully and successfully verified live — these questions are about the *personal, authenticated* RVO integration path (Mijn percelen), which is explicitly out of this sprint's scope but was researched enough to know it's a real, existing program, not a hypothetical one.

1. **What reuse licence applies to BRP Gewaspercelen specifically?** Confirmed via the live OGC API's own `rel="license"` link: **Public Domain Mark 1.0**. This is more permissive than the CC-BY-4.0 named on PDOK's general copyright page for four *other* named datasets. Please confirm Public Domain Mark 1.0 is indeed authoritative for BRP Gewaspercelen specifically (not just a default the API happens to link), and that no attribution is legally required (we intend to display source attribution anyway, as good practice, regardless of the answer).

2. **What are the service limits/SLA for the OGC API (`api.pdok.nl/rvo/gewaspercelen/ogc/v1`)?** No rate limit or SLA was documented on any page we reviewed. Given this dataset only updates annually, our integration caches search results for 6 hours client-side — please let us know if a formal limit exists that we should respect instead.

3. **Which dataset is current and which is definitive, when a new year's data is still being finalized?** We observed "BRP Gewaspercelen 2025 definitief," published 2026-03-17, with a peildatum (reference date) of 15 May 2025 — i.e., roughly a 10-month lag between the reference date and general availability. Is there a preliminary/non-definitief version available earlier in the year, and if so, should software distinguish "definitief" from provisional data explicitly to users?

4. **Is there a supported, authenticated route for farmers to import their own Mijn percelen data into third-party farm-management software?** We found that RVO operates a real webservices program for software developers (`https://www.rvo.nl/onderwerpen/webservices`), requiring the requesting software system to be registered/known to RVO in advance and connecting via eHerkenning (a PKI certificate is required for some webservices). We have NOT attempted to register FarmOS with this program — this sprint deliberately treats personal Mijn-percelen import as a future partnership integration, not something to build speculatively. Please confirm: (a) is this webservices program open to a farm-management SaaS vendor like ours, (b) what is the registration process and typical timeline, and (c) is there a sandbox/test environment available before committing to production access?

5. **Is eHerkenning the only supported authentication method for this integration, or is an OAuth-style flow available for third-party applications?** eHerkenning is described everywhere we found as tied to a farm's own KVK (Chamber of Commerce) registration and requiring at least trust level 2+ — we'd like to understand whether a third-party app can broker this on a farmer's behalf (similar to how banking apps use iDIN/PSD2) or whether each farmer must independently hold their own eHerkenning credential to authorize any integration.

6. **Are software vendors eligible for direct RVO webservice access without an existing enterprise/reseller relationship?** Given FarmOS is a small, early-stage product (see `FarmOS_Complexity_Kill_List.md`'s own "designed for one farm manager, not an enterprise" framing), we want to understand whether RVO's program has a minimum scale/vetting requirement that would make this impractical before a much later stage of the product's life.
