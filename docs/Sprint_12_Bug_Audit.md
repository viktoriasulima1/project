# Sprint 12 — Visual and Interaction Bug Audit

Found via actually running the app in a real browser through Playwright (not code review alone) — every P0/P1 below was caught because a real test hit it, then confirmed fixed by re-running the same test. P2/P3 items were noticed while reading the surrounding code during this pass but are not blocking and were not fixed this sprint.

## P0 — blocking, all fixed

1. **No way anywhere in the product to create a Machine/sprayer**, yet spraying strictly requires selecting one (`activities.ts`'s `superRefine`, Sprint 11). A brand-new user could never complete their first spray activity. **Fixed:** `src/lib/actions/machines.ts` (new, minimal `createMachine` action) + an inline "+ Add a new sprayer" control in `ActivityDialog.tsx`'s Sprayer field.
2. **Onboarding wizard's step transitions raced with the ready-user auto-redirect guard.** Every transition called a bare `router.refresh()`, which re-fetches whatever the *current* URL happens to be. Real network/DB latency meant an earlier step's refresh (e.g. the field step's) could still be in flight when a later step (crop assignment) made `setupState` flip to `ready` for the first time — when that stale refresh finally resolved, it still carried no `step` param, hit `shouldRedirectReadyUserToDashboard`, and silently sent the user straight to `/dashboard`, skipping the optional inventory/employee steps and the Review screen entirely. **Fixed:** every transition in `OnboardingWizard.tsx` now calls `router.replace('/onboarding?step=<next>')` instead of a bare refresh.
3. **Sidebar had zero responsive behavior** — a fixed 216px column, always rendered, no way to hide it. On a 390px-wide mobile viewport it permanently occupied over half the screen. **Fixed:** `Sidebar.tsx`/`Sidebar.module.css` now hide it by default below 768px behind a hamburger toggle, sliding in as an overlay with a backdrop.
4. **`createActivity` never verified `machineId` ownership** — `fieldSeasonId` and `productId` were checked against the current farm, `machineId` was not. A crafted request with another farm's machine id would have been silently attached to an activity with no rejection. **Fixed:** added the missing ownership check in `activities.ts`, confirmed by a new unit test and by `isolation.spec.ts`'s live cross-farm attempt.
5. **Quick Log's desktop trigger overlapped the Activities page's own "+ Record activity" toolbar button** — both occupied the same top-right region below the topbar. Confirmed directly by Playwright's own retry log ("intercepts pointer events"). **Fixed:** moved the desktop trigger to bottom-right (`QuickLogButton.module.css`), a corner no page's own content occupies.

## P1 — high severity, all fixed

6. **`onboarding_completed` fired on every render of `/onboarding?done=1`**, not just the first — a refresh, browser back/forward, or a second detour through an optional step's own Finish click would each re-fire it, violating "retries do not duplicate success events" (Sprint 12 Part 12's own requirement). **Fixed:** added `Farm.onboardingCompletedAt` (new nullable column, migration `20260712192708_sprint12_onboarding_completed_guard`) and gated the event on it being unset.
7. **Quick Log's "View activity history" success button didn't navigate** when opened from any page other than `/activities` — it just closed the dialog and refreshed in place, silently breaking its own promise. **Fixed:** `QuickLogButton.tsx`'s `handleSuccess` now pushes to `/activities` unless already there.
8. **Muted text color failed WCAG AA contrast almost everywhere** — `#6e7681` on `#161b22` measured 3.76:1 against the 4.5:1 minimum for normal text; axe-core flagged it as `serious` on nearly every page. **Fixed:** `--color-text-muted` changed to `#828a94` in `globals.css`.
9. **`ActivityDialog` had no focus trap and no Escape-to-close.** It renders `<dialog open>` as a static attribute rather than calling `.showModal()`, so none of the browser's native modal behaviors applied — a keyboard user could Tab straight out into the sidebar/topbar behind the "modal." **Fixed:** added manual Tab-cycling and Escape handling in `ActivityDialog.tsx`.
10. **Validation error banners had no `role="alert"`** (`ActivityDialog.tsx` and all six in `OnboardingWizard.tsx`) — a screen reader would not announce them appearing. **Fixed:** added `role="alert"` to all seven.
11. **Dialog title was a plain `<div>`, not a semantic heading**, and the close button had no accessible name beyond the "×" glyph. **Fixed:** changed to `<h2 id="activity-dialog-title">` with `aria-labelledby` on the dialog, and `aria-label="Close"` on the button.

## P2/P3 — noticed, not fixed this sprint

- **No localized (Dutch, comma-decimal) number formatting.** Stock/dose values render via plain `.toFixed()` (e.g. `"500.000"`), not `toLocaleString('nl-NL')`. Dates already correctly use `toLocaleDateString('nl-NL', ...)` (`ActivitiesClient.tsx`) — numbers don't. Given the product's explicit Dutch-farmer audience, this is a real but non-blocking polish item.
- **No currency formatting** confirmed for the Finance module's monetary values (not deeply exercised this sprint — Finance remains a thin snapshot view).
- **No background-scroll lock behind the activity dialog.** The overlay covers the viewport, but `<body>` itself isn't given `overflow: hidden` while a dialog is open — on a touch device, a two-finger/edge gesture could still scroll the page behind it. Minor; not confirmed as user-visible in testing.
- **Long field/product names untested for table overflow.** `ActivitiesClient.tsx`'s table has no `text-overflow`/`white-space` handling verified against a genuinely long Dutch farm or field name (e.g. a long `Maatschap` name) — plausible truncation/wrap issue, not exercised this sprint.
- **No CLS/loading-flicker measurement performed.** `Button.tsx`'s spinner-toggle-via-CSS pattern (from an earlier sprint) was specifically designed to avoid a mount/unmount flicker, but no automated Cumulative-Layout-Shift check was run this sprint to confirm it holds under real network latency.
- **Timezone display beyond spray-window logic not audited.** `getAmsterdamDateString()` (`spray-window.ts`) is deliberately Amsterdam-anchored for spray-day logic; whether every other displayed timestamp consistently reflects `Farm.timezone` (default `Europe/Amsterdam`) was not systematically checked page-by-page this sprint.
